# 产品模式设计说明

## 背景

当前工具已经能完成“输入需求、生成澄清问题、回答问题、生成最终 Brief”的完整链路，但实际使用中会出现一个重要问题：很多用户请求并不是宏大项目需求，例如 debug、改一段文案、整理一句提示词、让 Agent 看一个局部问题。此时继续要求用户填写完整背景、目标用户、范围、验收标准，反而会把简单表达复杂化。

因此，后续产品应从单一“需求分析器”改为用户开始前可选择的双模式：

1. 格式优化模式
2. 头脑风暴模式

用户在开始前自行选择模式。

## 模式一：格式优化模式

### 定位

格式优化模式是轻量 Prompt 整理器。它服务于“用户已经知道要做什么，只是表达不够清楚”的场景。

### 适用场景

- debug 或报错排查
- 局部代码修改
- UI 文案或样式微调
- 翻译、润色、总结
- 整理一段口语化需求
- 把零散想法改写成更适合发给 Agent 的请求

### 核心原则

- 不主动追问。
- 不生成宏大的项目任务书。
- 不把简单请求扩展成完整产品 brief。
- 保留用户真实意图。
- 只做条理化、精炼化、格式化。
- 允许少量基于专业场景的补全，但必须在备注中说明。
- 不编造用户没有表达的事实。

### 专业场景补全

LLM 可以识别常见场景，并补充少量执行上天然需要的流程要求。

例如 debug 场景中，可以补充：

- 复现问题
- 定位根因
- 做最小范围修复
- 说明修改位置
- 说明验证方式
- 避免无关重构

但这些补全必须在备注中透明说明，例如：

> 基于 debug 场景，补充了复现路径、根因定位、最小修复和验证说明；未扩展新的功能目标。

### 页面展示

格式优化模式结果页展示三块：

1. 原文
2. 优化后 Prompt
3. 备注

备注只用于说明 LLM 做了哪些少量专业补全，不应喧宾夺主。

### 输出形态

输出应是轻量 Prompt，例如：

```markdown
请帮我定位并修复当前按钮点击无响应的问题。

请重点完成：
- 复现按钮无响应的触发路径；
- 检查事件绑定、状态更新、组件 props 传递和控制台错误；
- 找到根因后做最小范围修复；
- 修复后说明问题原因、修改位置和验证方式。

注意：
- 不要做无关重构；
- 不要改动与该问题无关的功能。
```

不应默认输出完整的“背景、目标、范围、功能需求、非功能需求、验收标准”等大型任务书。

## 模式二：头脑风暴模式

### 定位

头脑风暴模式是交互式需求澄清助手。它服务于“用户还没完全想清楚，需要 AI 一步步引导”的场景。

### 交互方式

- LLM 一次只问一个问题。
- 优先问最能推进需求清晰度的问题。
- 用户每回答一轮，LLM 都更新右侧实时摘要看板。
- 右侧看板不是字段表单，而是一份不断生长的需求摘要。
- 摘要只记录已经确认下来的细化需求。
- LLM 每轮自评需求清晰度。
- 当 LLM 认为需求大约 95% 清楚时，主动询问用户是否收束需求。
- 用户随时可以点击“收束需求”按钮，不必等待 LLM 建议。

### 实时摘要看板

看板应像会议纪要或需求白板，而不是结构化表格。

示例：

```markdown
当前已明确的需求：

用户想做一个 Windows 桌面端工具，用来把模糊需求整理成可交给 Agent 执行的 Prompt。

目前确定：
- 工具需要区分“轻量格式优化”和“深度头脑风暴”两种模式。
- 格式优化模式只做表达精炼，不应把简单请求扩展成大型项目 brief。
- 头脑风暴模式需要逐轮提问，并在每轮后沉淀更清晰的需求摘要。
- 用户希望在 LLM 判断需求大约 95% 清楚后，询问是否收束。
```

### 收束逻辑

当 LLM 建议收束时，页面询问：

> 我认为当前需求已经基本清楚，可以收束成 Prompt。是否现在结束头脑风暴？

用户选择：

- 是：结束头脑风暴，生成最终 Prompt。
- 否：不是取消，而是在按钮位置展开输入框，让用户说明还想继续讨论什么。

用户也可以随时手动点击“收束需求”。

### 最终输出

头脑风暴模式收束时，根据复杂度自动选择输出形态：

- 小任务：输出轻量 Prompt。
- 复杂项目：输出完整任务书。

复杂度由 LLM 根据需求范围、模块数量、交付物复杂度、约束数量和执行周期判断。

## 对现有实现的影响

当前的“生成 3-7 个澄清问题，再生成完整 Brief”更接近头脑风暴模式的早期雏形，但需要改造成逐轮发问和实时摘要。

后续推荐优先级：

1. 先实现格式优化模式，尽快解决简单需求被过度复杂化的问题。
2. 再改造头脑风暴模式，从一次性问题列表改为逐轮交互。
3. 最后增加基于复杂度的自动收束输出选择。

## 验收标准

- 用户开始前必须能选择格式优化模式或头脑风暴模式。
- 格式优化模式不会追问用户，不会默认生成完整任务书。
- 格式优化结果包含原文、优化后 Prompt 和备注。
- 备注会说明所有基于专业场景的补全。
- 头脑风暴模式一次只问一个问题。
- 每轮回答后实时摘要看板都会更新。
- LLM 可以自评清晰度并在约 95% 时建议收束。
- 用户可以随时手动收束。
- 用户拒绝收束时，可以输入继续探索方向。
- 头脑风暴收束后能根据复杂度自动选择轻量 Prompt 或完整任务书。
